# Mini Typeless 网络故障应急步骤

适用：录音完成后报连接中断（例如 -1005），无法得到本次文字。首先尝试恢复连接，不急于改代码、换模型、换旧版或修改代理规则。

## 一步一步操作

1. 如果当前待重试录音有需要保留的内容，先点击“另存待重试录音”。Standby Fix 成功开始下一段录音会替换旧临时录音；正常退出也会清除临时副本。
2. 保持 WiFi 连接，在加速器（本次为 Shadowrocket）中关闭连接开关。只断开加速器，不修改节点、规则、DNS 或 IPv6 设置。此时依赖加速器的网站可能暂时无法访问。
3. 使用当前 Mini Typeless 版本录一句短测试话，Fn 开始、Fn 停止，检查是否得到文字并插入。打开百炼网页只能辅助判断，不能代替这一步。
4. 如果关闭加速器后能正常运行，重新打开加速器的连接开关（断开再开启），保持原配置和节点，再用同一版本录一句短话验证。
5. 如果重新开启后也成功，即可继续使用。如果仍失败，不保证多次开关能修好；先保留需要的录音，记录版本、发生时间、错误文字，以及加速器开/关时各自的结果，再排查。

若要保留并处理刚才失败的同一段音频，可选择“重试转写（重新上传）”，而不是新录音；重试可能重复计费，成功后按现有规则复制或手动插入。2026-10-21 的故障恢复测试验证的是恢复 WiFi 后新录音替换，并未重新验收手动上传旧段。

## 本次有效的实例与边界

2026-10-21 用户报告：关闭加速器时，百炼网页可访问，Stable Rollback 和 Standby Fix 都能正常运行；重新开启加速器后，Standby Fix 在 ChatGPT、Claude、Obsidian 中的 Fn 转写插入、合盖后开盖自动处理、新录音替换失败段均成功。

这是本次有效的应急恢复方法，不是“只要关闭时能用，重新开启就必定能用”的保证。故障暂未复现，根因未确认；不能因此断言 IPv6、某个节点或代码改动就是根因。此前提议的固定 IPv4 映射未执行，现阶段无需实施。
