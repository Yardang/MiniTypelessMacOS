# 转写失败诊断测试版

本轮针对十分钟验收中的 `HTTP 400 / CLIENT_ERROR` 增加可观察信息及最小复现入口。尚未取得这次真实失败的服务端详细说明，不能认定静音就是原因，也不把任何未知 400 错误自动跳过。

## 改动边界

- `DictationPipeline` 提取共用的单片段转写方法，正常录音和合成测试使用相同请求、模型、超时及解析逻辑。
- `ServiceDiagnostic` 接收选定错误字段，显示失败片段序号、片段时长、HTTP 状态、错误码、请求 ID 和经过脱敏的云端说明。密钥、常见认证字段、URL、音频 Data URI、长编码串及控制字符被隐藏或移除，说明限制为 500 字符；不保存完整服务端响应。
- 普通录音的详细错误只在窗口内显示；底部提示最多三行，完整说明放入可滚动结果区，防止挤走复制按钮。
- Debug 测试版增加“检测静音转写（上传合成音频）”。测试代码集中在 `ASRDiagnostics.swift`，不会使用麦克风，也不会进入整理或插入流程。
- 仍使用原有 Touch ID 会话解锁；钥匙串读取、保存、迁移函数及访问组保持不变。用户自行在系统弹窗中解锁，开发工具不读取真实密钥。

## 合成测试

依次进行三次 ASR 请求，无自动重试：

1. 约 3.84 秒合成语音：“这是合成语音测试，项目名称是蓝鲸。”用于对照请求与服务是否可用。
2. 120 秒全零 PCM 静音，模拟十分钟录音最后一个无讲话片段。
3. 240 秒音频，在约第 1 秒及第 180 秒放入相同短句，中间和末尾为全零静音。

音频已生成，无需实时录制或等待十分钟。请求计入接口用量；成功响应的用量仍沿用现有统计。每个请求上限 120 秒，三项独立展示结果，一项失败仍可继续其他对照项。“诊断结束”只表示请求结束，不代表三项均通过。

合成纯静音与实际麦克风的背景噪声并不相同：即使复现相同错误，也需结合详细原因判断，不能直接证明原始录音的失败原因。

## 操作

1. 保存旧版窗口中需要的文字；从 Dock 右键退出旧版。当前版本的 Command-Q 已知不可用，本轮未修改它。
2. 打开 `/Users/yardang/Applications/Mini Typeless ASR Diagnostics.app`，标题应为“Mini Typeless · 转写诊断测试”。
3. 点击“用 Touch ID 解锁本次运行”，然后点击“检测静音转写（上传合成音频）”。无需录音或勾选兼容插入。
4. 等待“静音诊断结束”。需要中断时点击“取消当前处理”。睡眠也会停止后续测试。
5. 告知开发者测试完成即可。报告位置会显示在窗口中，名称为 `MiniTypeless-ASR-Diagnostic-<UUID>.txt`，保存在当前用户临时目录。报告仅包含合成测试项目、耗时及脱敏错误，不含识别全文、请求正文或密钥；不会自动发送给任何人。

诊断不改变此前成功结果和原始转写。临时报告可能被系统清理；窗口中也可选中复制。尚未处理的录音存在时，不启动诊断。
