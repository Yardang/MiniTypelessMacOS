# 录音与自动插入：结构排查及修复

## 判断

先整理与故障直接相关的职责边界，再修复并回归；不先做全项目重写。

排查起点是 `SecureProbe` 约 1,358 行，集中管理 AppKit 窗口、快捷键、麦克风、定时器、网络、费用、钥匙串和粘贴。另有先前拆出的焦点解析模块。文件长本身不能证明是 bug 根因；实际风险是同一流程由多个入口分别推进，且异步回调读取可变的全局状态。

## 发现的具体问题

1. Fn 停止先调用 `toggleRecording()`，再额外调用 `processRecording()`；120 秒定时器只调用前者。因此达到时限不会自动转写，下一次 Fn 甚至会开始新录音并清理旧文件。停止按钮也有不同的行为。
2. 插入只看整理完成那一刻的前台应用。等待期间切回 Mini Typeless，会落入“应用未列入范围”，没有记录预期接收应用，提示也不显示实际应用。
3. 用户截图中已有 120 秒录音的 ASR 和整理耗时，证明那次已经完成转写；截图不能证明 Fn 事件丢失，也不能确定当时的前台应用。实际跨应用插入仍需用户验证。
4. 直接把 120 改成 600 不够：16 kHz 单声道 16 bit PCM 的十分钟数据约 19.2 MB，超过旧代码的 10 MB 本地检查；当前模型单次上限为五分钟。
5. 整理输出固定 1,200 tokens，未检查 `finish_reason`，长录音可能把被截断的结果当成功结果。
6. 既有测试覆盖布局和焦点查询，没有覆盖停止录音到生成结果的完整链路。

## 本轮职责边界

| 文件 | 负责什么 |
| --- | --- |
| `RecordingController.swift` | 麦克风、600 秒硬限制、定时器、完成事件；用户停止和限时停止只通知一次；丢弃不上传 |
| `AudioChunks.swift` | 解析录音 WAV、验证 PCM 参数、无损拆成不超过 240 秒的片段 |
| `DictationPipeline.swift` | 按顺序转写片段、汇总用量事件、合并全文后整理一次、取消与结果完整性检查；可替换网络传输以离线测试 |
| `InsertionDestination.swift` | 记录停止时目标应用，决定保持当前目标、从 Mini Typeless 返回原应用或停止自动插入 |
| `InputFocus.swift` | 已有的有界辅助功能查询和输入框验证 |
| `MiniTypelessSecureApp.swift` | AppKit 视图、将上述事件连接到界面、实际粘贴；本轮保留既有钥匙串和用量持久化逻辑 |

录音：按 Fn 开始 → 再按 Fn／点击停止／600 秒到期 → 同一个停止回调 → 自动转写各片段 → 合并整理 → 更新最新结果 → 尝试插入一次。若本次运行尚未通过 Touch ID 解锁，则明确提示先解锁，并保留录音供手动继续；不会越过解锁步骤。

目标应用在停止录音时冻结；如果此时位于 Mini Typeless，则沿用开始录音时的外部应用。完成时仍在目标应用，正常检查焦点；若在 Mini Typeless，激活原目标并重新检查；若位于第三个应用，停止自动插入并显示两边的应用名称。窗口内具体输入框仍须在粘贴前确认，兼容模式仍按用户勾选允许无焦点粘贴，并不保证自动找到正确对话框。手动“尝试插入”和“兼容粘贴”继续允许用户重新选择。

长录音在内存中分段，所有 PCM 样本按原顺序保留一次，不重复上传相邻样本，不生成额外音频文件。片段边界可能影响语音识别上下文；不会通过重叠片段制造重复文字。部分转写失败不会把不完整内容当作最新成功结果或自动插入。取消／睡眠后迟到的响应不会更新结果。费用按每个返回的成功请求累计，整段录音耗时按实际样本总量显示。

整理按原文长度增加输出额度；未以正常 `stop` 结束的输出不插入。现有轻度整理提示和保守检查保持不变。

## 验证与边界

- 离线用合成十分钟 WAV 验证样本无丢失、无重复、分段大小、元数据填充及非法音频。
- 用假的录音设备和网络传输驱动实际 App 协调代码：手动停止、限时停止、重复完成、取消／睡眠后的迟到响应。
- 覆盖目标应用路由、片段中途失败、整理截断、旧定时器和旧录音回调。
- 既有 15 项焦点解析和 24 组窗口布局测试继续运行。
- 离线测试不能证明真麦克风持续录制十分钟、真实云端长音频效果或 Codex 实际接收粘贴。应在新构建中验证这些交互。
- 测试使用合成密钥和音频，不读取用户钥匙串、不调用百炼、不把合成用量写入用户统计。

下一阶段可单独整理 AppKit 视图、用量仓库、钥匙串服务和诊断工具。当前先隔离引发故障的生命周期；不以机械拆文件替代职责整理。
