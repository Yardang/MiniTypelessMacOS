# 窗口重开崩溃与本地诊断日志

## 证据和修复

本机 `~/Library/Logs/DiagnosticReports/` 中最近五份 MiniTypelessSecure 应用报告，均为 `EXC_BAD_ACCESS / SIGSEGV`，主线程在 `objc_msgSend` → `SecureProbe.applicationShouldHandleReopen(_:hasVisibleWindows:)` 崩溃：

- 2026-10-19 06:24:26、06:15:21（-0400）：断网恢复版。
- 2026-10-17 11:22:39：转写诊断版。
- 2026-10-16 10:23:44、09:57:55：较早用量测试版。

这些报告证明本次已找到一种反复发生的真实崩溃；不能据此排除尚未记录的其他退出原因。测试程序名带 regression 的报告不计入应用崩溃。

程序由 delegate 持有并重复使用同一个手动创建的 NSWindow，但此前没有设置 `isReleasedWhenClosed = false`。关闭窗口后，AppKit 默认释放窗口，再次响应 Dock 等重新打开事件时就可能访问失效对象。[Apple 的文档](https://developer.apple.com/documentation/appkit/nswindow/isreleasedwhenclosed) 明确要求 Swift/ARC 客户端设置 false，避免过度释放。

本次设置为 false，保留窗口与结果，关闭窗口仍不退出程序；重开时增加窗口存在检查。没有改动 Fn、录音时限、云端模型、钥匙串访问方法或 Cmd-Q 行为。

## 新增日志

独立模块 `DiagnosticLog.swift`；目录 `~/Library/Logs/MiniTypeless/`。界面上方可滚动区域底部新增“打开本地诊断日志”。

- 记录时间、随机会话编号、进程号、诊断构建编号；处理操作有独立编号。
- 记录启动、窗口关闭/重开、睡眠/唤醒、正常退出；录音开始/停止/到期、转写分段、整理、成功/失败/取消、手动重试/删除/另存、跳过插入或发出粘贴请求。
- 错误只记录固定分类、数字系统码/HTTP 状态和片段序号。不会保存任意错误描述、网络响应正文、用户文件路径、窗口标题、录音、转写/整理文字、剪贴板或密钥。
- `events.jsonl` 为当前日志，`events.1.jsonl` 为最近备份，最多另保留三份各 256 KiB 文件，总量约 1 MiB。日志权限 0600，新建目录 0700。
- 关键事件及时落盘；写入失败不影响录音处理，日志入口会提示无法使用。日志不会上传。
- `terminationRequested` 表示进入退出清理，`cleanTermination` 表示清理完成。缺少正常退出记录只意味着会话可能中断，也可能因强制退出、掉电、写盘失败或日志轮转，不能单独当成崩溃证明；需与同一进程/时间的 macOS `.ips` 报告交叉核对。
- 不安装自定义崩溃信号处理器；系统报告保留崩溃堆栈，应用日志提供此前运行阶段。本轮没有加入跨启动录音/文字恢复。
