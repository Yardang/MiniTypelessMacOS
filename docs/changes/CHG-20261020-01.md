# CHG-20261020-01 — 睡眠待机与连续录音

状态：开发完成，七组自动测试及构建签名通过；真实睡眠验收待用户完成。关联需求：MT-SLP-001/002/003、MT-REC-003/004、MT-SEC-001、MT-ERR-001。

## 问题与证据

稳定性版日志显示睡眠清除了会话密钥；用户再次录音 1.749 秒后因未解锁无法处理。后续 Fn 事件均被接收，但待重试录音规则阻止了新录音。此前规则旨在防丢数据，实际给连续使用造成阻塞。

用户 2026-10-20 明确选择：允许系统睡眠，睡前结束录音、唤醒自动处理；旧待重试段保留到下一段成功开始才自动删除。用户同时要求统一 PRD、明确索引、严格变更与测试流程，并要求对含糊需求先澄清。

## 实现计划

1. 将已确认行为写入 PRD，标明替代的旧规则与数据影响。
2. 拆出小型会话睡眠状态模块，集中管理待唤醒任务的消费/失效，不扩大为全面架构重写。
3. 录音控制器以独立新文件启动下一段，成功后清理旧文件；失败回退旧段。
4. 协调层保留跨睡眠解锁状态、暂停录音并一次性恢复；取消/重复通知/新任务隔离。
5. 补充定向自动测试；运行原有相关回归、Debug/Release 构建与签名检查。
6. PRD/README/日志说明同步，独立安装，旧版保留；记录代码版本、构建指纹、自动测试与待实测项。
