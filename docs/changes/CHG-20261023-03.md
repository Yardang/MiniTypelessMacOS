# CHG-20261023-03 — 录音提示比重与折叠尺寸恢复

状态：开发完成，用户实机复看待验。关联 MT-UI-002/003、MT-WIN-001。

用户已确认 Preview 2 的玻璃外观满意，仅要求两处修改：录音胶囊以中间时长为主，右侧小字“Fn 结束”；展开上次结果后收起，应恢复展开前的窗口大小。

范围：只改 StatusHUD 的录音布局、ResultWindow 的展开/收起尺寸管理。保持三种主题、材质、颜色和核心录音/转写/插入流程。Fn 提示仍为说明文字，不新增点击结束行为。

验收：录音胶囊时长居中、提示靠右且字号较小；处理/失败提示仍能正常显示；默认或手动调整过的窗口展开后可恢复原尺寸，重复状态刷新不会覆盖恢复尺寸；新录音导致自动折叠同样恢复。保持窗口当前左上角位置，展开期间用户移动窗口后不跳回原位置。

验证计划：先增加可复现旧版折叠缺陷的回归，再验证布局/窗口重开与 Debug/Release 构建。沿用已有核心测试及用户外观结论，不要求重复断网、睡眠或长录音。

## 实现与证据

- 录音胶囊保持 300 × 48 pt 和原玻璃；左侧小红点/波形，中间 15 pt 等宽数字时长，右侧 11 pt“Fn 结束”，分开布局。非录音阶段沿用原状态行、旋转进度和查看按钮；没有增加录音按钮或焦点行为。
- 原缺陷原因：render 仅提高最小高度，收起时没有保存/恢复展开前尺寸。现在只在首次展开时保存尺寸，收起恢复；重复渲染不覆盖快照。尺寸变化保持当前左上角，保留展开期间的移动位置；收起恢复原宽高。新录音或清空导致自动折叠也走同一恢复逻辑。
- 新增回归在旧代码上明确失败：`Collapsing did not restore original size`；修复后通过。覆盖 580×430、640×480、720×700 三种初始尺寸，每种反复展开/刷新/收起三次，以及展开后移动、新录音自动折叠。
- 36 组布局检查、胶囊时长居中/提示靠右/字号层级/失败状态切换检查通过；25 次窗口关闭重开回归通过。Debug 签名构建和 Release 编译通过。
- 自建合成背景上的实际胶囊截图已人工检查：波形、居中时长、分隔线及右侧小字均完整。没有截取或保存用户原文。
- 未改录音、转写、插入、钥匙串或主题材质；沿用此前核心回归和实机结论。不要求用户重复全部测试。
