# 转写断网后的录音恢复

> 历史记录：睡眠清除解锁、待重试录音阻止新录音的规则由 [CHG-20261020-01](changes/CHG-20261020-01.md) 替代。最新行为以 [PRD](PRD.md) 为准；本页保留当时测试结论。

## 本次证据及原因

用户截图显示：静音片段修复版、转写片段 1/1、90.4 秒、系统代码 -1005，并明确显示“录音已删除”。这说明已停止录音并进入 ASR 请求，不能据此判定 Fn 没有响应。

[Apple 对 -1005 的说明](https://developer.apple.com/library/archive/qa/qa1941/_index.html)：承载请求的连接在进行过程中断开。仅凭该码不能进一步区分本地网络、代理或远端服务的问题，也不能确定云端是否已完成处理。

此前实现读入 WAV 并分段后立即调用 `clearAudio()`，随后才等待网络响应；网络失败释放任务后，本地既无原文件也无返回文字，无法重试。这是应用的数据恢复缺陷。本轮只查找应用命名规则下的临时 WAV 元数据，未找到与本次时长和日期对应的录音；没有读取其他用户音频。现有本地副本无法恢复本次内容。

## 修复后的生命周期

| 状态 | 临时录音 | 用户操作 |
| --- | --- | --- |
| 转写／整理进行中 | 保留，恢复按钮暂不可用 | 可取消处理 |
| 请求失败、全无文字或输出检查未通过 | 保留；已有转写和此前成功结果仍可查看 | 手动重试、另存 WAV、主动删除 |
| 取消处理 | 保留已结束录音，不再接收迟到结果 | 重试／另存／删除 |
| 处理时或失败后睡眠 | 保留已结束录音，清除会话密钥 | 唤醒后 Touch ID 解锁才能重试；另存不需要密钥 |
| 尚在录音时睡眠 | 沿用原有停止并丢弃行为，不触发上传 | 唤醒后重新开始 |
| 成功处理 | 删除临时副本，结果留在窗口 | 正常首次处理仍按原有策略尝试插入 |
| 主动删除、正常退出 | 删除临时副本 | 用户另存文件不受影响 |

恢复仅保证本次运行中的副本；没有加入跨启动恢复、历史录音库或崩溃恢复。需要长期保留时，应先点击“另存待重试录音…”。

## 重试及防覆盖

- 底部固定区域新增“重试转写（重新上传）”“另存待重试录音…”“删除待重试录音”，最小窗口仍可见。
- 有待恢复录音时，开始录音按钮及 Fn-start 不会覆盖它；录音控制器也拒绝直接覆盖未清除的已结束录音。
- 重试会重新上传整段录音并重新转写、整理；没有自动循环重试或从中间片段续传。此前请求可能已在云端处理，重复请求可能再次产生费用。
- 重试失败不清掉此前已取得的原始转写；重试成功更新最新结果、删除临时音频，但不会自动恢复旧目标或粘贴。用户可复制结果或使用现有手动插入入口选择接收位置。
- 录音损坏或未解锁时同样保留文件供另存／删除，避免下一次录音覆盖它。
- WAV 导出通过系统保存面板由用户选择路径；保存失败时源文件保留。
- 钥匙串、签名身份、模型、静音响应规则和正常 Fn 停止后的自动处理方式不变。
